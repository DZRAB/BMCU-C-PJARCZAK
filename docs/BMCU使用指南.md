# BMCU 使用指南

> 面向使用者：如何为你的硬件与打印机选对固件、刷写、校准，以及使用中的注意事项。
> 开发细节见 [`BMCU开发说明.md`](./BMCU开发说明.md)，编译方法见 [`编译指南.md`](./编译指南.md)。

---

## 1. 这个固件是做什么的

BMCU-C 是 **Bambu Lab AMS（自动多色换料系统）的开源替代固件**，运行在第三方 BMCU 370C 硬件上，使 4 通道 filament 切料/换料器像原厂 AMS 一样被打印机识别与控制：多色自动换料、filament 装入/回抽/卸载、空通道校准、堵塞与防卡保护、AUTOLOAD 自动装载、filament 元数据掉电持久化、RGB 状态指示。

固件通过半双工 RS485 与打印机通讯，支持两套协议：
- **BambuBus**（`0x3D`）：BMCU 直接挂在打印机 AMS 总线上时
- **AHUB**（`0x33`）：BMCU 通过 AMS HUB 串联时

## 2. 固件选型（这么多固件是干嘛的）

仓库提供大量固件变体，是因为装入力、自动装载、LED、槽位、回抽长度都需要按你的硬件与打印机组合来定。变体按下面四个维度组合，对应 `firmwares/` 目录树（由 `build_all_firmwares_softload.sh` 或 `build_all_firmwares_fast.py` 生成，二者输出完全一致；或从 **GitHub Releases** 下载）。

> 每个维度的详细选型理由见仓库根目录 `which_to_choose_*.txt`（编译时会复制到对应目录层）。下面只给结论速查。

### 2.1 装入力模式（顶层目录）

| 模式 | 适用场景 |
|------|----------|
| `standard(A1)` | 默认。A1 等 PTFE 管较短且较直（摩擦小）的配置 |
| `high_force_load(P1S)` | P1S 或 PTFE 路径长/多弯折，装入力更大；装入被拒绝/失败时优先切这档 |
| `soft_load(A1)` | 仅 A1/A1 Mini。装入时听到打磨/咔哒声、想降低 BMCU 磨损时试用；可能装入被拒，优先方案是换更强的压力弹簧 |

**不确定就从 `standard(A1)` 开始。**

### 2.2 AUTOLOAD（双微动开关板）/ NO_AUTOLOAD（单开关板）

两者对应**不同硬件版本**，**不要混用**：

- **AUTOLOAD = 双微动开关板（DM）**：板上有 S1、S2 两个微动开关（S1 在进料口侧、S2 在出料口/挤出机后方侧）。装料先触发 S1，再被 BMG 齿轮咬住、继续前进触发 S2（两开关都触发 = 完全到位），随后自动再送约 12cm 就位。**退料时用第二个开关 S2 自动判定料根位置（自动回抽，v3.0-autoretract 起），无需在编译期选择回抽长度**——固件文件名带 `_auto` 后缀（如 `ams_a_2.00f_auto.bin`），其中的 `2.00` 仅作安全上限。默认发布的双开关固件都是这种自动回抽版；若你的 S2 开关不可靠、或想用固定回抽长度，可单独编译双开关固定回抽长度档（文件名不带 `_auto`，如 `ams_a_0.30f.bin`，见 [`编译指南.md`](./编译指南.md) 的 `AUTO_RETRACT=0`）。两种回抽方式对比见 2.5 节。
- **NO_AUTOLOAD = 单开关板**：板上只有 1 个开关，无自动装入（须手动把 filament 推到 PTFE 管里可见）；退料也**无法用 S2 判定料根**，因此仍需按 PTFE 长度选择对应回抽长度固件。
- 混刷后果：单开关固件刷到双开关板会忽略第二个开关、丧失自动装入与自动回抽；双开关固件刷到单开关板则第一阶段须手动推料（降级手动模式）。除非清楚后果，请按硬件版本选择对应文件夹。

### 2.3 FILAMENT_RGB_ON / FILAMENT_RGB_OFF

仅影响前 LED 是否在装入后显示 filament 颜色，**无其他行为变化**。想要安静/无灯环境选 `FILAMENT_RGB_OFF`。

### 2.4 槽位与回抽长度（SOLO / AMS_A~D）

- **SOLO**：单 BMCU。双开关板用自动回抽（`solo_2.00f_auto.bin`，无需选长度）；单开关板固定 9.5 cm（`solo_0.095f.bin`）。
- **AMS_A~D**：多 BMCU 配置（2–4 台，每台必须用不同槽位），或单台但需要更长回抽。
- 回抽长度从打印机内部 **AMS 分线器末端** 起算，加一点安全余量使 filament 清过分线器。例如到分线器约 9 cm，则选 9.5 cm 档。P1 配置常因 PTFE 更长而需更长的回抽。**回抽长度范围：双开关板（AUTOLOAD）无需选择，固件用 S2 自动判定（每槽仅 `ams_x_2.00f_auto.bin` 一个）；单开关板（NO_AUTOLOAD）SOLO 固定 0.095 米（9.5 cm），AMS_A~D 支持 0.10~2.00 米（步长 5cm，共 39 档：0.10/0.15/…/2.00），按 PTFE 实际长度选择对应档位。**

### 2.5 两种回抽方式（自动回抽 vs 固定回抽长度）

退料时 filament 要往回抽多少、抽到哪停，本固件有两种做法，区别只在**料根位置怎么判定**：

| | 自动回抽（默认，`_auto` 固件） | 固定回抽长度（不带 `_auto`） |
|---|---|---|
| 适用硬件 | 仅双开关板（AUTOLOAD）；单开关板无 S2，无法用 | 全部硬件（单开关板本就如此；双开关板设 `AUTO_RETRACT=0` 也可） |
| 料根判定 | 退料时由第二个微动开关 **S2 自动判定**：S2 一释放即停，再自动送约 12cm 就位 | 由你编译时选定的**固定长度**决定，退到该长度即停 |
| 选型难度 | 无需量 PTFE，直接选 `xxx_2.00f_auto.bin` 即可 | 需按 PTFE 实际长度从 39 档里挑一档（见上「回抽长度范围」） |
| 文件名 | 带 `_auto` 后缀，如 `ams_a_2.00f_auto.bin`（`2.00` 仅安全上限） | 不带 `_auto`，如 `ams_a_0.30f.bin` |
| 何时选 | 双开关板、S2 工作正常的默认推荐 | S2 不可靠 / 想沿用固定长度习惯时；或单开关板必然如此 |

**一句话**：双开关板默认用自动回抽最省心（不用量管子）；固定回抽长度则要求你按实际 PTFE 长度挑档，和单开关板一样。两者只是「料根怎么停」的不同，最终都能正常换料。

> 双开关板要编译固定回抽长度固件的方法见 [`编译指南.md`](./编译指南.md) 的 `AUTO_RETRACT=0`；单开关板固定长度矩阵由全量脚本直接产出。

## 3. 刷写固件

> ⚠️ **本仓库固件不支持 BMCU Flasher**。BMCU Flasher 仅适用于原作者原版固件，用它刷本仓库固件会失败。请使用 **WCHISPTool** 烧录。

1. 从 **GitHub Releases** 下载对应变体的 `firmware.bin`，或用 [`编译指南.md`](./编译指南.md) 自行编译。
2. 用 **WCHISPTool**（WCH 官方 ISP 工具）烧录：将芯片 **BOOT0 拉高、BOOT1 拉低** 进入系统 bootloader，通过 USB 或 USB-TTL 串口连接，选择芯片 **CH32V203**，载入 `firmware.bin` 后点「下载 / 烧录」；烧完把 BOOT0 拉低、复位即可运行。
   - 具体 BOOT 引脚位置、USB/串口焊盘以 BMCU 370C 板实物为准（板子未引出时需接烧录测试点）。
3. 若有 **WCH-Link** 调试器，也可用 `pio run -e <env> -t upload` 直接烧录。

详细步骤与接线见 [`编译指南.md`](./编译指南.md) 的「六、刷写固件」。

## 4. 打印机配置与兼容性

- 打印机必须配置为 **AMS**，而不是 **AMS Lite**；使用 AMS Lite 会导致兼容性问题。
- Bambu Lab 正通过固件更新限制本地 BMCU 的互通性，详见 [`bmcu-vs-firmware-locks.md`](./bmcu-vs-firmware-locks.md)。
- 打印机启动会报 **HMS 警告**（来自心跳握手），属已知可接受行为，**不阻断打印**。
- **打印机固件版本**：当前 BMCU 固件最高兼容打印机固件 **1.07.00**（即 Bambu 版本号 `01.07.00.00` 的简写，详见 [`bmcu-vs-firmware-locks.md`](./bmcu-vs-firmware-locks.md) 第 4 节写法说明）；建议将打印机固件降到 **1.07.00 之前** 的版本，以获得最佳兼容性与稳定性。Bambu 后续固件更新可能进一步收紧互通性，详见 [`bmcu-vs-firmware-locks.md`](./bmcu-vs-firmware-locks.md)。

## 5. 校准

正确校准是 BMCU 正常工作的前提。校准会记录每个通道的「无 filament」检测点（空闲电压）、霍尔（磁铁）极性、DM 微动开关阈值，并存入 Flash（掉电不丢失）。

### 5.1 首次装机校准（详细步骤）

> 校准前请确保所有通道为空（未装入 filament）。上电后固件会**逐通道引导**你完成缓冲结构的机械行程校准，按下面流程依次操作即可。

1. **上电自检**：给 BMCU 上电，等待上电自检通过。
2. **通道 1 进入校准**：自检通过后，**通道 1 的 RGB 灯珠开始闪烁（正常为蓝灯）**，表示等待该通道校准。
3. **向内压到底**：用手将通道 1 的缓冲结构**向内按压到最低（压到底）**，保持约 **1 秒** 后松开。
4. **向外拉到最大**：此时灯珠**变为红灯闪烁**，表示等待外极限；将缓冲结构**向外拽到最大（拉到最外）**，保持约 **1 秒** 后松开。
5. **通道 1 完成**：该通道校准数据写入，灯珠停止闪烁，固件**自动切换到通道 2** 进入校准（蓝灯闪烁）。
6. **循环校准**：按第 3~5 步依次完成通道 2、3、4。四个通道全部校准完成后，校准结束，BMCU 即可被打印机识别。

> 校准视频参考（原作者）：https://www.youtube.com/watch?v=Hn_DNzSmhuc

### 5.2 重新校准

任何时候都可重新校准（例如装入识别不准、更换硬件后）：

1. **取出所有通道的 filament**（必须为空）。
2. **将任意一个缓冲结构向内按压到底**，保持约 **5 秒**，固件即进入与首次上电相同的逐通道校准流程（见 5.1，从第 2 步蓝灯闪烁开始）。
3. 按 5.1 的第 3~6 步依次完成四个通道即可。

### 5.3 多 BMCU 配置

多台 BMCU（AMS_A~D）**每台需各自校准**：分别清空、各自上电首次校准（或各自按住 buffer 重校）。

- filament 元数据与已装入状态掉电持久化，断电后可续打。

## 6. 使用注意事项

- **二代打印机不被识别**：多为 RS485 信号 A/B 接反，可尝试对调（需明确自己在做什么）。
- **系统灯含义**：浅灰为正常（有 AHT20 时每 3 秒闪一下、无 AHT20 时常亮）；红色为总线错误。
- **AHT20 版本（v2.0-aht20 引入，v2.1-aht20 更新）额外注意**：
  - `PB10`/`PB11`（AHT20 的 SCL/SDA）需外接 **4.7kΩ 上拉到 3.3V**（模块通常自带，裸片需补）。
  - 这两脚原被 USART3 调试串口占位；未开启调试输出时安全，若开启调试日志需另选引脚或关闭 AHT20。
  - 温湿度由现有协议自动上报给打印机，无需额外设置。
  - 未焊接 AHT20 时，固件不报错、不影响换料与通信，温湿度按默认值 **22°C / 20%** 上报（与原作者程序行为一致，打印机端显示恒定在此值）。
  - **怎么判断板子上有没有 AHT20（3.2.1）**：上电自检发 5 次测量命令，靠校准使能位（bit[3]，硬件上电自动置 1、软件写不了）确认芯片真存在，再校验物理范围（湿度 0–100%、温度 −40–85℃）和忙标志；任一次通过就认在线，5 次全败认无传感器。工作中连续 10 次采样失败就当传感器掉了，温湿度退回默认 22/20、停止采样，成功一次即恢复。
  - **系统灯与 AHT20 的关系（3.2.1）**：AHT20 在板子上离系统灯很近，灯常亮白光会发热烤高读数，所以焊了 AHT20 的板子系统灯改成**每 3 秒闪一下白光（约 150ms）、其余时间熄灭**；没焊 AHT20 的板子系统灯白色常亮（无传感器可烤，保持原样）；通讯异常时红色常亮。
  - **无 AHT20 时的温湿度模拟测试（调试用）**：源码内置 `sim_aht20_probe_step()`（`src/sim_aht20.cpp`）。它在**每次响应打印机 `filament_motion_long` 查询**时（`bambu_bus_ams.cpp` 的 `get_package_stu_motion` 内调用）将温度 +1℃、湿度 +10%（到 50℃/100% 回绕），使打印机屏幕上温湿度随其查询周期逐格跳变——用秒表量相邻两次数字变化的时间间隔，即为打印机拉取温湿度的周期（例如每 1 秒变一次即 1 秒查询一次）。
    - **开关方式**：打开 `src/sim_aht20.h`,将顶部 `#define SIM_AHB_PROBE_ENABLE 1` 改为 `0` 即关闭（改为 `1` 即开启）。**改文件保存后重新编译即可，无需任何命令行或编译宏传参**，对所有编译方式（pio / 全量脚本 / 快速脚本）通用。关闭时 `sim_aht20_probe_step()` 为空操作。
    - **AHT20 实物焊接到位后**：将 `SIM_AHB_PROBE_ENABLE` 设为 `0`、改用真实传感器即可，无需改动其他代码。
    - 此功能仅用于测试，正式发布固件建议设为 `0`。
- **多 BMCU 配置**：每台必须使用不同槽位固件（AMS_A~D），并各自校准。

## 7. OLED 状态屏（可选，`BMCU_OLED`）

> 适用：想**不上机也能肉眼看 BMCU 当前状态**的用户（温湿度、通讯是否连上、四通道料况）。屏幕是**可选配件**，不焊/不定义 `BMCU_OLED` 时固件与无屏版完全一致。

### 7.1 硬件与接线

- 屏幕：SSD1306 驱动 0.96" I2C OLED（128×64 单色），I2C 地址 `0x3C`。
- **与 AHT20 共用同一条软件 I2C 总线**（PB10=SCL、PB11=SDA，开漏 + 外部 4.7k 上拉）——**不新增任何引脚**，焊了 AHT20 的板子直接并接 OLED 即可。
- 两设备共用总线时确保 4.7k 上拉到位（AHT20 模块通常自带，OLED 模块也各自补上拉）。

### 7.2 编译 / 刷写

- 单编某个固件时，给 `build_one.sh` 第 11 参数传 `1` 启用：
  ```bash
  bash build_one.sh standard 1 1 SOLO 0.095 1 GFU85 GFU85 GFU85 GFU85 1   # 末尾 1 = 开 OLED
  ```
- 全量脚本（`build_all_firmwares_fast.py`）当前未设 OLED 开关；需要全量带屏版时单独编对应变体即可。
- 屏幕初始化在 BMCU 与打印机**首次通讯成功**后进行；之后每秒刷新一次（整屏重绘）。

### 7.3 显示内容与约定

OLED 与 **RGB 灯是同一套状态信息的两种呈现**（和 RGB 一样，不上机也能提示用户）。显示约定遵循现有状态含义，避免整屏乱跳：

| 显示区域 | 内容 | 含义 |
|---|---|---|
| 第 0~1 行 | 温度 / 湿度（如 `T:23.5C` `H:45%`） | AHT20 实时温湿度；未焊 AHT20 时显示 `AHT20 OFFLINE` |
| 第 2 行 | `LINK: OK` / `LINK: ERR` | BMCU 与打印机通讯状态；没连上显示 `ERR`，提示检查 RS485（与 SYS_RGB 系统灯红灯掉线逻辑一致）|
| 第 3~6 行（规划中）| 四通道料况 | 每通道显示「空 / 有料 / 进料中 / 推料中」及当前料类型，与通道 RGB 灯含义对齐 |

> 当前已提交版本显示温湿度 + 通讯状态行；四通道料况为下一步待实现（实现时会按上表约定显示，与 RGB 联动）。

### 7.4 常见问题

- **屏幕不亮**：确认 `OLED=1` 已编入、PB10/PB11 上拉到位、OLED 模块地址为 `0x3C`。
- **温湿度不显示 / 显示 OFFLINE**：同 AHT20 章节（第 6 章），多因 AHT20 没焊或上拉不对；不影响换料与通讯。
- **整屏刷新有"卡顿感"**：当前刷新率 1Hz 整屏重绘，属正常现象（不影响性能，仅视觉）。后续会提高刷新率并改局部刷新。
