# BMCU-C 编译指南

本工程**不使用 MounRiver Studio**，基于 **PlatformIO + 社区 CH32V 平台**（`Community-PIO-CH32V`）构建。所有编译变体定义在 `platformio.ini` 中，但该文件**严禁改动**——所有自定义宏一律通过脚本注入。

---

## 一、环境准备

只需准备以下基础工具，编译器和 SDK 由 PlatformIO 首次编译时**自动下载**：

| 依赖 | 作用 | 是否自动安装 |
|------|------|--------------|
| **Python 3** | PlatformIO 运行环境 | 需自行安装 |
| **git** | 首次编译需从 GitHub 克隆 `Community-PIO-CH32V` 平台源码 | 需自行安装 |
| **PlatformIO (pio)** | 构建系统 | 需自行安装：`pip install platformio` |
| **联网** | 拉取平台包 + RISC-V GCC 工具链 + WCH noneos-sdk | 需联网 |
| **RISC-V GCC / WCH noneos-sdk** | 实际编译器 | ✅ 自动下载 |

> **Windows 用户提示**：在 **Git Bash / PowerShell / CMD** 中执行命令均可，只要 `pio` 和 `git` 在 PATH 中。若使用 **VSCode 的 PlatformIO 插件**，它自带 Python 和 pio，打开工程后直接点 Build 即可（仍需系统安装 git）。

安装验证：

```bash
python --version    # 或 python3 --version
git --version
pio --version
```

## 二、两种编译方式总览

| 方式 | 脚本 | 产物目录 | 用途 |
|------|------|----------|------|
| 编译单个固件 | `build_one.sh` | `single_build/` | 单独补编某一个固件 |
| 编译全部固件 | `build_all_firmwares_fast.py` | `firmwares/` | 生成完整发布矩阵 |

> `single_build/` 与 `firmwares/` 均被 `.gitignore` 忽略、不入库。两者目录结构与命名规则完全一致，可互相并入。

## 三、编译单个固件（build_one.sh）

### 3.1 命令格式

```bash
bash build_one.sh <MODE> <AUTOLOAD> <RGB> <SLOT> <RETRACT> [AUTO_RETRACT] [TPU0 TPU1 TPU2 TPU3]
```

### 3.2 位置参数说明

| 位置 | 参数 | 取值 | 缺省 | 含义 |
|------|------|------|------|------|
| 1 | `MODE` | `standard` \| `p1s` \| `softload` | `standard` | 推力模式：standard(A1) / high_force_load(P1S) / soft_load(A1) |
| 2 | `AUTOLOAD` | `1` \| `0` | `1` | 双微动开关板=1，单微动开关板=0 |
| 3 | `RGB` | `1` \| `0` | `1` | ONLINE LED 是否显示 filament RGB |
| 4 | `SLOT` | `SOLO` \| `A` \| `B` \| `C` \| `D` | `SOLO` | AMS 槽位；SOLO 回抽默认 0.095 |
| 5 | `RETRACT` | 浮点(米)，如 `0.30` | SOLO=`0.095` | 回抽长度 |
| 6 | `AUTO_RETRACT` | `1` \| `0` | `1` | 仅对双开关(AUTOLOAD=1)生效：1=自动回抽(`_auto`，忽略第5参数)；0=双开关也按固定长度矩阵(第5参数生效) |
| 7~10 | `TPU0~TPU3` | 见下「写死型号」 | 全 `GFU85` | 槽 0~3 的 TPU 写死型号 |

> **回抽长度何时被忽略**：当 `AUTOLOAD=1` 且 `AUTO_RETRACT=1`（默认）时，回抽由第二个微动开关 S2 自动判定，第 5 参数无效，文件名加 `_auto` 后缀，固件内部以 `2.00m` 作安全上限。

### 3.3 写死型号（TPU0~TPU3）

v4.0-tpu 所有固件**无条件内置 TPU 逻辑**。打印机只允许设置 TPU for AMS（`GFU98`），其它 TPU 型号被拒；编译期用 `TPU0~TPU3` 给 4 个通道分别写死型号，运行时某通道被设为 `GFU98` 时忽略下发、内部用写死型号跑（回传仍是 `GFU98`，循环不触发，详见 `BMCU开发说明.md` 第 14 章）。

取值须为 `tpu_params.h` 参数表中存在的型号前缀：

```
GFU98 / GFU00 / GFU02 / GFU95 / GFU90 / GFU85
```

缺省全 `GFU85`（最软最稳）。写死型号**不新增变体维度**（固件数不变），也不体现在文件名中。

### 3.4 示例

```bash
# 双开关自动回抽（默认全开），产物 solo_2.00f_auto.bin
bash build_one.sh standard 1 1 SOLO

# 双开关固定长度模式，产物 ams_a_0.30f.bin
bash build_one.sh standard 1 1 A 0.30 0

# 单开关(NO_AUTOLOAD)，产物 ams_d_0.80f.bin
bash build_one.sh p1s 0 1 D 0.80

# 4 通道写死型号：SLOT0=GFU98 SLOT1=GFU90 SLOT2=GFU95 SLOT3=GFU85
bash build_one.sh standard 1 1 A 0.30 1 GFU98 GFU90 GFU95 GFU85

# 单开关也可写死（一般全 GFU85 保底）
bash build_one.sh p1s 0 1 D 0.80 1 GFU85 GFU85 GFU85 GFU85
```

### 3.5 可选编译宏（环境变量注入）

以上位置参数已覆盖槽位/回抽/写死型号。另有 5 个**开关类宏**通过环境变量注入（不传即用缺省）：

| 环境变量 | 取值 | 缺省 | 含义 |
|----------|------|------|------|
| `BMCU_OLED` | `1`/`0` | `1` | OLED 状态屏总开关；老主板无屏传 `0` 剥离驱动省 Flash/RAM |
| `BMCU_AHT20` | `1`/`0` | `1` | AHT20 温湿度传感器开关；老主板无传感器传 `0` 剥离驱动 |
| `BMCU_TPU_ENABLE` | `1`/`0` | `1` | TPU 送料逻辑总开关；`0`=关闭 TPU 回到 v3.2 刚性 |
| `BMCU_AUTO_REBOOT_ENABLE` | `1`/`0` | `0` | 打印完成空闲后软复位；**默认关**，仅部分机型需要传 `1` 开启 |
| `BMCU_OLED_DEBUG` | `1`/`0` | `0` | OLED 调试页（抓包+未知指令记录）；上机排查通讯传 `1` |

> 以上宏全部经 `PLATFORMIO_BUILD_FLAGS` 注入，**不修改 `platformio.ini`**（严禁改动）。OLED/AHT20 即使编入固件，运行时也会自动探测硬件是否存在（无屏/无传感器零影响）。
>
> 注意：`BMCU_OLED` 与 `BMCU_AHT20` 用**值判断**（`#if defined(...) && (...+0)`），`=0` 时驱动**编译期彻底不编入**（实测可省 OLED≈4.5KB Flash / 2.1KB RAM、AHT20 约 1.5KB Flash / 数十字节 RAM）。`BMCU_OLED_DEBUG` 用 `#ifdef` 判断（只看是否定义、不看值），故脚本仅在 `=1` 时注入 `-DBMCU_OLED_DEBUG`，`=0` 时不注入（保持未定义）。

示例：

```bash
# 老主板：剥离 OLED + AHT20 驱动
BMCU_OLED=0 BMCU_AHT20=0 bash build_one.sh standard 1 1 SOLO

# 针对需重启机型开启自动重启
BMCU_AUTO_REBOOT_ENABLE=1 bash build_one.sh standard 1 1 SOLO

# 上机排查通讯：开 OLED 调试页
BMCU_OLED_DEBUG=1 bash build_one.sh standard 1 1 SOLO
```

## 四、编译全部固件（build_all_firmwares_fast.py）

### 4.1 基本用法

```bash
python build_all_firmwares_fast.py              # 默认：双开关自动回抽，共 972 个
AUTO_RETRACT=0 python build_all_firmwares_fast.py   # 双开关也出固定回抽长度矩阵，共 1884 个
```

> 原 `build_all_firmwares_softload.sh`（作者慢速脚本）已删除——不支持 v4.0-tpu 新宏注入且速度慢。全量编译统一用本脚本。

### 4.2 4 通道写死型号（环境变量 BMCU_TPU_FIX0~3）

与单固件脚本的 `TPU0~TPU3` 等价，但用环境变量传入：

```bash
# 默认：4 通道全 GFU85（最稳），共 972 个
python build_all_firmwares_fast.py

# 写死 4 通道：SLOT0=GFU98 SLOT1=GFU90 SLOT2=GFU95 SLOT3=GFU85
BMCU_TPU_FIX0=GFU98 BMCU_TPU_FIX1=GFU90 BMCU_TPU_FIX2=GFU95 BMCU_TPU_FIX3=GFU85 \
  python build_all_firmwares_fast.py     # 仍为 972 个，每固件带写死表

# 叠加双开关固定回抽长度矩阵
BMCU_TPU_FIX0=GFU98 BMCU_TPU_FIX1=GFU90 AUTO_RETRACT=0 python build_all_firmwares_fast.py
```

取值同单固件：`GFU98/GFU00/GFU02/GFU95/GFU90/GFU85`（缺省全 `GFU85`）。写死表并入现有变体编译，**不新增变体维度**（固件数不变 972 / 1884）。

### 4.3 环境变量与配置项（脚本顶部）

| 变量 | 缺省 | 含义 |
|------|------|------|
| `AUTO_RETRACT` | `1` | 仅对双开关(AUTOLOAD)生效。`1`=自动回抽(每槽 1 个 `_auto`，共 972)；`0`=双开关也按固定长度矩阵(每槽 39 档，共 1884)。单开关(NO_AUTOLOAD)不受此变量影响 |
| `BMCU_TPU_FIX0~3` | `GFU85` | v4.0-tpu 新增。槽 0~3 写死 TPU 型号，并入所有变体编译，不增变体数 |
| `BMCU_OLED` | `1` | SSD1306 OLED 状态屏总开关；老主板无屏传 `0` 剥离驱动省 Flash/RAM |
| `BMCU_AHT20` | `1` | AHT20 温湿度传感器开关；老主板无传感器传 `0` 剥离驱动。关闭时务必保持 `BMCU_USE_HW_I2C2` 默认开 |
| `BMCU_TPU_ENABLE` | `1` | TPU 送料逻辑总开关；`0`=关闭 TPU 回到 v3.2 刚性 |
| `BMCU_AUTO_REBOOT_ENABLE` | `0` | 打印完成空闲后软复位；**默认关**，仅部分机型需要传 `1` 开启 |
| `BMCU_OLED_DEBUG` | `0` | OLED 调试页开关；用 `#ifdef` 判断，脚本仅在 `=1` 时注入 `-DBMCU_OLED_DEBUG` |
| `FAST_MODE` | `True` | `True`=二进制修补回抽长度(最快)；`False`=每档回抽长度重编 Motion_control.cpp(字节级一致但更慢) |
| `OUT_DIR` | `firmwares` | 常规固件输出目录 |
| `MAX_JOBS` / `LINK_JOBS` | 自动 | 可覆盖并行编译线程数与最大并发链接数 |

> 高速模式（默认 `FAST_MODE=True`）下，因 LTO 链接顺序/分区差异，生成的 `.bin` 与 `pio run -e fw` 存在字节级差异，但功能完全等价（已通过宏差异、回抽长度修补差异验证）。如需字节级一致产物，设 `FAST_MODE=False`。

### 4.4 编译矩阵与产物说明

脚本遍历 **打印机模式 × {双开关自动回抽(AUTOLOAD), 单开关(NO_AUTOLOAD)} × RGB × 槽位**（含 `soft_load(A1)` 模式），生成完整 `firmwares/` 目录树（含 `manifest.txt` 校验清单）。

- **编译矩阵**：3 种模式 × {AUTOLOAD(每槽 1 个) , NO_AUTOLOAD(SOLO×1 + AMS_A~D×39)} × RGB_ON/OFF = **972 个**；设 `AUTO_RETRACT=0` 升到 **1884 个**。
- **双开关(AUTOLOAD)**：每槽仅 1 个 `xxx_2.00f_auto.bin`，回抽由 S2 自动判定，`2.00` 仅作安全上限。
- **单开关(NO_AUTOLOAD)**：SOLO 固定 9.5cm；AMS_A~D 每槽 0.10~2.00 米、步长 5cm 共 39 档。
- **目录结构**：`standard(A1)/`、`high_force_load(P1S)/`、`soft_load(A1)/` → `AUTOLOAD/NO_AUTOLOAD` → `FILAMENT_RGB_ON/OFF` → `SOLO/AMS_A~D/`。
- **文档文件**：每个层级带 `README.md`（由根目录 `which_to_choose_*.txt` 复制改名自动生成，勿手改）。
- **校验文件**：`firmwares/manifest.txt`（每行：`SHA256 CRC32 大小 相对路径`）。

> 脚本开头执行 `rm -rf firmwares` 后重建——**会删除现有 `firmwares/`**（已被 `.gitignore` 忽略，误删只能重跑或下 Releases）。**耗时提醒**：约 972 次 `pio run`，耗时长（实测数小时），建议后台运行勿打断。

### 4.5 高速原理简介

- **工具链参数提取**：`pio run -e moj -v` 提取编译/链接命令行并缓存（首次提取后，只要 `platformio.ini` 未改动即复用）。
- **共享编译**：不受变体宏影响的 `.o`（Framework SDK + 不变用户源）只编译一次；受宏影响的源按「模式组合」编译并缓存复用。
- **回抽长度二进制修补**：`AMS_RETRACT_LEN` 仅作用于 `Motion_control`，基础固件以占位符浮点 `123.456f` 编译，最终在 `.bin` 中将该浮点二进制替换为目标回抽长度，省去为每档重编。
- **写死型号宏全程并入**：`BMCU_TPU_FIX0~3` 无条件追加进所有变体编译 flags，不读废弃的 `BMCU_TPU_MODEL`、不再有 TPU 隔离分支。

> **缓存目录 `.pio_parallel/`**（自动生成，已被 `.gitignore` 忽略）：存放 `verbose_cache.txt`（工具链命令行缓存）与 `obj_cache/`（预编译 `.o` 按模式组合缓存）。可放心删除（下次运行自动重建）；若改了 `platformio.ini` 或工具链后结果异常，删除它强制重建缓存。

## 五、用 fw 环境手动传参（完全自定义）

若需脚本未覆盖的组合（如特殊 `soft_load` + 自定义宏），可用 `[env:fw]` 从环境变量读取全部编译宏：

```bash
BAMBU_BUS_AMS_NUM=0 \
AMS_RETRACT_LEN=0.095f \
BMCU_DM_TWO_MICROSWITCH=1 \
BMCU_ONLINE_LED_FILAMENT_RGB=1 \
DBMCU_P1S=0 \
BMCU_SOFT_LOAD=0 \
pio run -e fw
```

各宏含义：

| 宏 | 取值 | 含义 |
|----|------|------|
| `BAMBU_BUS_AMS_NUM` | `0`~`3` | AMS 槽位编号，对应 A~D（SOLO 用 `0`） |
| `AMS_RETRACT_LEN` | 浮点(米) | 回抽长度，如 `0.095f` = 9.5 cm |
| `BMCU_DM_TWO_MICROSWITCH` | `0`/`1` | 双微动开关板 + AUTOLOAD（`1`=开）；`0`=单开关板 |
| `BMCU_DM_AUTO_RETRACT` | `0`/`1`（随双开关派生：双=1、单=0） | 自动回抽开关（仅双开关有效）：`1`=S2 自动判定料根；`0`=双开关固定长度矩阵。区别见 [`BMCU使用指南.md`](./BMCU使用指南.md) 2.5 节 |
| `BMCU_ONLINE_LED_FILAMENT_RGB` | `0`/`1` | 装入后 ONLINE LED 显示 filament 颜色（`1`=开）。**v4.0-tpu 写死色行为**：某通道被设为 TPU 时显示该通道**写死型号**色（青/绿/紫/黄/橙/红，见 `BMCU开发说明.md` 14.4 的 `TPU_FIXED_ID`），非 TPU 统一白偏蓝。用于肉眼验证内部实际型号 |
| `DBMCU_P1S` | `0`/`1` | P1S 模式（`1`=开，高力加载） |
| `BMCU_SOFT_LOAD` | `0`/`1` | soft_load(A1) 软加载模式（`1`=开） |
| `BMCU_OLED` | `0`/`1`（默认 `1`） | OLED 状态屏总开关。运行时自动探测屏，无屏零影响；老主板无屏传 `0` 彻底剥离驱动 |
| `BMCU_AHT20` | `0`/`1`（默认 `1`） | AHT20 温湿度传感器开关。关闭时务必保持 `BMCU_USE_HW_I2C2` 默认开（OLED 走硬件 I2C2） |
| `BMCU_TPU_ENABLE` | `0`/`1`（默认 `1`） | TPU 送料逻辑总开关。`0`=全工程关闭 TPU 回到 v3.2 刚性 |
| `BMCU_AUTO_REBOOT_ENABLE` | `0`/`1`（默认 `0`） | 打印完成空闲后软复位总开关。**默认 `0`（关）**，仅部分机型传 `1` 开启 |
| `BMCU_OLED_DEBUG` | `0`/`1`（默认 `0`） | OLED 调试页（抓包+未知指令记录）。用 `#ifdef` 判断，脚本仅在 `=1` 时注入 `-DBMCU_OLED_DEBUG` |
| `BMCU_TPU_FIX0~3` | 见写死型号 | 4 通道写死 TPU 型号（注入方式与脚本一致） |

> **关于双开关固定回抽长度模式**（`BMCU_DM_AUTO_RETRACT=0`）：默认双开关=1（自动回抽）。仅当「双开关硬件却想要固定回抽长度」时编译（如 S2 不可靠/个人偏好），触发后双开关也出 39 档固定长度矩阵（总数升到 1884）。两种回抽方式区别见 [`BMCU使用指南.md`](./BMCU使用指南.md) 2.5 节。

## 六、宏开关总对比（编译传参 vs 手动改文件）

v4.0-tpu 所有功能开关**都通过脚本注入，不手动改 `src/` 头文件**（头文件侧保留 `#ifndef ... #define ... 缺省值` 仅作兜底）。为方便一眼区分「脚本传参」与「手动改文件」，列出完整表：

| 宏 | 用法 | 含义 | 缺省 | 注入/修改位置 |
|----|------|------|------|---------------|
| `BMCU_TPU_FIX0~3` | 编译传参 | 4 通道写死 TPU 型号（GFU98/GFU00/GFU02/GFU95/GFU90/GFU85） | 全 `GFU85` | `build_one.sh` 第 7~10 参数；`build_all_firmwares_fast.py` 环境变量 `BMCU_TPU_FIX0~3` |
| `BMCU_DM_TWO_MICROSWITCH` | 编译传参 | 双/单微动开关板（AUTOLOAD/NO_AUTOLOAD） | 由 MODE/AUTOLOAD 决定 | `build_one.sh` 第 2 参数；批量脚本已写死 |
| `BMCU_DM_AUTO_RETRACT` | 编译传参 | 双开关自动回抽开关 | `1`（开） | `build_one.sh` 第 6 参数；环境变量 `AUTO_RETRACT` |
| `BMCU_ONLINE_LED_FILAMENT_RGB` | 编译传参 | FILAMENT_RGB 开/关 | 由 RGB 参数决定 | `build_one.sh` 第 3 参数；批量脚本已写死 |
| `BMCU_SOFT_LOAD` / `DBMCU_P1S` | 编译传参 | 推力模式（soft_load / standard / high_force_load） | 由 MODE 参数决定 | `build_one.sh` 第 1 参数；批量脚本已写死 |
| `BAMBU_BUS_AMS_NUM` | 编译传参 | 本机 AMS 槽位（SOLO/A/B/C/D） | 由 SLOT 参数决定 | `build_one.sh` 第 4 参数；批量脚本已写死 |
| `AMS_RETRACT_LEN` | 编译传参 | 回抽长度（米） | 由 RETRACT 参数决定 | `build_one.sh` 第 5 参数；批量脚本已写死 |
| `BMCU_OLED` | 编译传参 | OLED 状态屏总开关 | `1`（开） | 环境变量 `BMCU_OLED`；脚本注入 `PLATFORMIO_BUILD_FLAGS` |
| `BMCU_AHT20` | 编译传参 | AHT20 温湿度传感器开关 | `1`（开） | 环境变量 `BMCU_AHT20`；同上注入 |
| `BMCU_TPU_ENABLE` | 编译传参 | TPU 送料逻辑总开关 | `1`（开） | 环境变量 `BMCU_TPU_ENABLE`；同上注入 |
| `BMCU_AUTO_REBOOT_ENABLE` | 编译传参 | 自动重启（异常恢复）开关 | `0`（关） | 环境变量 `BMCU_AUTO_REBOOT_ENABLE`；同上注入 |
| `BMCU_OLED_DEBUG` | 编译传参 | OLED 调试页开关 | `0`（关） | 环境变量 `BMCU_OLED_DEBUG`；脚本仅 `=1` 时注入 |
| `BMCU_TPU_MODEL` | 已废弃 | 旧 TPU 专用固件分支 | 无 | 不再使用（v4.0 通用固件内置 TPU） |

**手动改源码的开关（仅特殊调试需求）**：正常无需改 `src/` 头文件，仅个别调试宏仍可直接 `#define`（都不碰 `platformio.ini`，改完重编）：

- **OLED 强制固定显示某页（调试）** — `src/oled/ssd1306_oled.h` 顶部 `BMCU_OLED_FORCE_PAGE`：未定义时正常轮询；定义后即固定显某页（排查用，测完删除）。

> **用法速记**：编译传参 = `build_one.sh` 位置参数 / `build_all_firmwares_fast.py` 环境变量（经 `PLATFORMIO_BUILD_FLAGS` 追加到所有环境）。**严禁改动 `platformio.ini`。**

## 七、编译产物位置

### 7.1 单变体编译（pio run -e xxx）

```
.pio/build/<env名>/firmware.bin
```

例如 `pio run -e moj` → `.pio/build/moj/firmware.bin`。同目录附带 `firmware.elf`（调试信息）、`firmware.map`（内存映射）。

> 若希望单固件也分目录并命名成 `solo_0.095f.bin` / `ams_a_0.30f.bin`，用 `build_one.sh`（见第三节），产物位于 `single_build/`。

### 7.2 单固件脚本（build_one.sh）

```
single_build/<MODE>/<AUTOLOAD|NO_AUTOLOAD>/<FILAMENT_RGB_ON|OFF>/<SLOT>/<bin名>
```

### 7.3 全量脚本（build_all_firmwares_fast.py）

```
firmwares/standard(A1)/AUTOLOAD/FILAMENT_RGB_ON/SOLO/solo_2.00f_auto.bin
firmwares/high_force_load(P1S)/AUTOLOAD/FILAMENT_RGB_ON/AMS_A/ams_a_2.00f_auto.bin
```

**TPU 写死型号**不新增产物目录，写死型号并入常规 `firmwares/` 矩阵（每个固件内置 4 通道写死表，由编译时 `BMCU_TPU_FIX0~3` 决定），不体现在文件名中，固件数维持 972 / 1884。

## 八、刷写固件

> ⚠️ **注意**：本仓库（BMCU-C）的二次开发固件**不支持 BMCU Flasher**（仅适用原作者原版固件）。请用 **WCHISPTool**（WCH 官方 ISP 工具）烧录本仓库编译出的 `firmware.bin`。

### 方式一：WCHISPTool（推荐，无需调试器）

通过 CH32V203 芯片内置**系统 bootloader** 烧录：

1. 让芯片进入系统 bootloader：将 **BOOT0 拉高、BOOT1 拉低**，然后上电/复位。
2. 连接电脑（二选一）：
   - **USB 方式**：接芯片的 USB D+/D-（CH32V203 系统 bootloader 自带 USB，WCHISPTool 直接识别）；
   - **串口方式**：通过 USB-TTL 适配器接系统 bootloader 对应的 USART（CH32V203 通常为 USART1，PA9/PA10）。
   - 具体 BOOT 引脚位置、USB/串口焊盘以你的 **BMCU 370C** 板实物为准（板子未引出时需接烧录测试点）。
3. 打开 WCHISPTool，选择芯片 **CH32V203**，载入 `firmware.bin`，点击「下载 / 烧录」。
4. 烧录完成后，将 **BOOT0 拉低** 恢复从 Flash 启动，复位上电即可运行。

### 方式二：PlatformIO + WCH-Link 调试器

```bash
pio run -e moj -t upload
```

普通刷写推荐用 WCHISPTool，无需额外调试器。

## 九、常见问题

**Q：第一次编译卡很久？**
A：正常。PlatformIO 正在后台下载 CH32V 平台包和 RISC-V GCC 工具链（需联网）。

**Q：提示找不到 `pio`？**
A：`pip install platformio` 并加入 PATH；或用 VSCode PlatformIO 插件。

**Q：提示找不到 `git`？**
A：安装 git 并确保可全局调用，平台包通过 git 从 GitHub 克隆。

**Q：想恢复被脚本误删的 `firmwares/`？**
A：`firmwares/` 已被 `.gitignore` 忽略、不受 git 跟踪，无法用 git 恢复；重新运行 `python build_all_firmwares_fast.py` 或从 Releases 下载。
