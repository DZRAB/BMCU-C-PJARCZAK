# BMCU-C 固件发布说明 —— v4.0-tpu（开发中）

> 适用机型：BMCU 切料机（CH32V203C8T6 / RISC-V 版）
> 固件向打印机上报的版本号保持 `10.50`，兼容性不变。
> 本版专门针对 TPU 这类软料做了送料优化，同时保留原有 PLA/PETG 行为。所有固件都内置 TPU 逻辑，**不再区分"通用固件 / 专用固件"**。
---

## 一、本次更新了什么

- **TPU 软料专用送料模式内置到所有固件**：BMCU 以前对 PLA / PETG 这类"硬料"送得很好，但对 TPU（橡胶一样的软料）支持不好——料会被缓冲头压着"压缩"而不是顺畅前进，经常误报堵料、或者电机空转啃料。v4.0 按 TPU 型号单独调了送料参数（推料力度、保持时间、报堵宽容度），让它也能稳定送料。这些参数**编进每一个固件**，无需编译开关切换。

- **每个 TPU 型号一套参数**：Bambu 的 TPU 有好几种，硬度差别很大（从 68D 的 TPU for AMS 到 85A 的极软 TPU），送料难度完全不同。v4.0 按型号分开调参：
  - `GFU98` Bambu TPU for AMS（68D，最硬，接近硬料）
  - `GFU00` Bambu TPU 95A HF / `GFU95` Bambu TPU 95A
  - `GFU02` Generic TPU for AMS
  - `GFU90` Bambu TPU 90A
  - `GFU85` Bambu TPU 85A（最软，参数最保守）

- **编译期「4 通道写死型号表」解决老打印机不支持 TPU 设置的问题**：打印机只允许设置 TPU for AMS（`GFU98`），其它 TPU 型号（95A/90A/85A 等）被拒。v4.0 允许在编译时**给 4 个通道分别写死一个型号**（`BMCU_TPU_FIX0~3`，默认全 `GFU85` 最软最稳）。当某通道被设为 TPU for AMS（`GFU98`）时，固件忽略下发的 `GFU98`，**内部用写死的型号跑软料参数**；非 TPU（PLA/PETG 等）仍走刚性逻辑，写死表不参与。详见第二节。

- **RGB 灯显示「内部真实写死型号」色**：关闭「耗材颜色显示」后，通道灯按 BMCU **实际跑的型号**点亮（如写死 95A 则黄灯），让你肉眼知道内部实际用哪个型号送料，而不是只看打印机下发的 `GFU98`。详见第三节。

- **主板系统灯（SYS_RGB）显示通讯心跳**：系统灯只负责 BMCU 与打印机的通讯状态——有 AHT20 时每 3 秒闪一下白光、无 AHT20 时常亮白光、通讯异常时红色。软料优化不涉及系统灯。

> 通道灯 = 每个料槽一颗（显示耗材色 / TPU 真实型号色）；系统灯 = 主板上单独一颗（显示通讯心跳）。两者是不同灯，别混淆。

## 二、核心机制：4 通道写死型号表（解决老打印机问题）

BMCU 是**多通道**的（4 槽 + SOLO），最常见的用法是**一个通道设 TPU、其他通道设 PLA/PETG 做支撑**——比如打 TPU 壳体、用 PLA 撑。这要求 BMCU 能按每个通道下发的材料，分别用不同推力参数送料。

### 2.1 打印机为什么只能设 GFU98

Bambu 打印机在材料设置里只允许选 **TPU for AMS（`GFU98`，filament_type == tpu）**。如果你在切片/打印机里选其它 TPU 型号（95A/90A/85A 等），打印机会拒绝设置，BMCU 也就收不到对应的 `filament_id`，TPU 软料参数不生效。

### 2.2 写死表怎么解决

v4.0 让固件在**编译时**就定好每通道要用的真实型号：

- 编译参数 `BMCU_TPU_FIX0~3` 分别指定槽 0~3 的写死型号（如 `SLOT0=GFU98 SLOT1=GFU90 SLOT2=GFU95 SLOT3=GFU85`）。**不指定时保底全写 `GFU85`**（最软最稳）。
- **运行时**：某通道被打印机设为 TPU for AMS（`GFU98`）时，固件忽略下发的 `GFU98`，**用该通道写死的型号跑软料参数**。
- **回传仍是 `GFU98`**——不骗打印机，循环不触发。这是本方案的核心优点：打印机以为自己设的是 `GFU98`，实际 BMCU 内部按你写死的 95A/90A/85A 送料，既绕开"只能设 GFU98"的限制，又不会因为回传型号不一致导致打印机反复重设。
- 非 TPU（PLA/PETG/ABS/PA/other）走正常刚性逻辑，**写死表不参与**。

> 举例：编译写死 `SLOT1=GFU90`。打印机里槽 1 设成 TPU for AMS（只能选这个）。BMCU 收到 `GFU98`，内部改用 `GFU90` 参数送料，回传仍是 `GFU98`，打印机一切正常，实际按 90A 软料跑。

### 2.3 没有写死需求时

不传任何 `BMCU_TPU_FIX*` 时，4 通道默认全 `GFU85`。此时只有打印机设为 `GFU98` 的通道会走 TPU 软料逻辑（用最保守的 85A 参数），其它通道照常刚性送料。这相当于"所有 TPU 都用最软最稳参数兜底"，是最省心的默认行为。

## 三、怎么确认 BMCU 内部实际用哪个型号（看 RGB 灯）

很多 TPU 送料问题，根因是"内部型号没对上"，结果在用不合适的推力推料。v4.0 加了一个**肉眼自检手段**：

- 把固件编译选项 **「耗材颜色显示」关掉**（即不选 `FILAMENT_RGB_ON` 那一级目录）。
- 装好料、通电后，看每个通道的**通道灯（每槽一颗）颜色**——它显示的是 **BMCU 内部实际跑的型号**（写死型号），不是打印机下发的 `GFU98`：

| 内部实际型号 | 型号 | 硬度 | 通道灯显示颜色 |
|---|---|---|---|
| GFU98 | TPU for AMS | 68D | 青 |
| GFU00 | TPU 95A HF | 95A | 绿 |
| GFU02 | Generic TPU | 约 68D | 紫 |
| GFU95 | TPU 95A | 95A | 黄 |
| GFU90 | TPU 90A | 90A | 橙 |
| GFU85 | TPU 85A | 85A | 红 |
| 非 TPU（PLA / PETG / ABS / PA / 未知 / other） | — | — | 白偏蓝（统一色） |

**怎么用**：
- 你写死的是 `GFU90`，LED 却显示**白偏蓝** → 说明该通道没被设为 TPU（打印机里是 PLA 等），写死表没生效，属正常。
- LED 显示**橙色** → BMCU 内部确实在按 `GFU90` 跑（虽然打印机下发的是 `GFU98`），正常送料即可。
- 颜色对得上你编译写死的型号，就证明"写死链路通畅"，后续送料问题就不在识别这一层。

> 注意：开「耗材颜色显示」时，LED 仍显示打印机下发的真实耗材颜色（原有功能不变），此自检表不生效。自检用**关掉**该选项的状态。

## 四、TPU 送料是怎么优化的（两类推力逻辑要分清）

TPU 的送料优化其实分**两套互相独立**的逻辑，别混为一谈：

**① 常态送料（占 99% 时间）**
装好料正常往前送时，BMCU 用"压力闭环"控制推力。TPU 越软，目标压力带和推力上限越低——避免硬顶把软料压扁、或推力过猛啃料。这是"平时怎么温柔推"。

| 料 | 类型 | 送料力度 | 相对 PLA |
|---|---|---|---|
| PLA / PETG / ABS / PA | 刚性 | 基准（原力度） | 基准 |
| GFU98 / GFU02（约 68D） | TPU 偏硬 | 略降 | 略降 |
| GFU00 / GFU95（95A） | TPU | 降约 10-15% | 降约 10-15% |
| GFU90（90A） | TPU | 降约 20-25% | 降约 20-25% |
| GFU85（85A） | TPU | 降约 30-40% | 降约 30-40% |

> 越软 → 推力越小、目标压力越低，软料"顶不满"不代表没在正常工作，只是温柔推进。

**② 顶满避让（只在卡料兜底时接管）**
当料卡在五通/进挤出机、缓冲头被持续顶到极限时才触发，分三段逐步减小推力温柔退避，避免硬顶死。TPU 越软，避让力度越小、报堵的容忍时间越长——软料弹性大、容易"假顶满"，给更长窗口才判定真堵。

| 料 | 避让力度（卡住时） | 报堵容忍 | 趋势 |
|---|---|---|---|
| PLA / PETG | 原力度 | 基准（约 5 秒） | v3.2 原值 |
| GFU98 / GFU02（约 68D） | 略小 | 略长（约 6 秒） | 略保守 |
| GFU00 / GFU95（95A） | 更小 | 更长（约 7 秒） | 更小/更宽 |
| GFU90（90A） | 更保守 | 更长（约 8 秒） | 更保守 |
| GFU85（85A） | 最保守 | 最长（约 9 秒） | 最保守/最长 |

**一句话区别**：常态送料管"平时怎么推"，顶满避让管"卡住了怎么退"。两者都按写死型号自动切换，非 TPU 仍走原 v3.2 逻辑。

## 五、主板系统灯（SYS_RGB）怎么显示通讯状态

> 这是**主板上单独一颗灯（SYS_RGB）**，不是各料槽的通道灯。它只负责显示 BMCU 与打印机的通讯状态，与软料优化无关。

| 系统灯状态 | 颜色 | 含义 |
|---|---|---|
| 启动瞬间 / 首心跳前 | 红（短亮） | 刚上电，还没和打印机建立通讯 |
| 通讯正常 + 无 AHT20 | 浅灰白 `0x38,0x35,0x32`（常亮） | 与打印机心跳正常 |
| 通讯正常 + 有 AHT20 | 浅灰白 **每 3 秒闪一下（约 150ms）** | 有 AHT20 时系统灯间歇闪烁，避免灯珠发热烤高温湿度读数 |
| 通讯失败 | 红 `0x10,0,0`（常亮） | BMCU 与打印机掉线 / 总线错误（严重故障） |

**怎么用**：
- 接了 AHT20、通讯正常时，系统灯是浅灰白底、每 3 秒闪一下 → 正常。
- 没接 AHT20、通讯正常时，系统灯是浅灰白常亮 → 正常。
- 系统灯变**红** = 和打印机掉线，按原有通讯问题排查。

> AHT20 是外接温湿度传感器（见 `BMCU开发说明.md` 第 12 章 / `BMCU使用指南.md`）。它只是辅助传感器——没接、坏了、或读不到，BMCU 都照常工作，温湿度走默认 22℃ / 20%。

## 六、怎么选固件（刷哪一个）

**只有一套固件**，不再区分通用/专用。选三点：**板型**、**打印机模式**、**PTFE 长度**，再加可选的 **4 通道写死型号**（`BMCU_TPU_FIX0~3`）。

1. **确认板型**：双开关 = AUTOLOAD；单开关 = NO_AUTOLOAD。
2. **确认打印机模式**：standard / p1s / soft_load(A1)（对应常规目录）。
3. **确认 PTFE 长度档**：见 `which_to_choose_slots.txt`。
4. **（可选）4 通道写死型号**：需要让某通道按特定 TPU 型号送料时，编译时传 `BMCU_TPU_FIX0~3`（见 `docs/编译指南.md`）。不传则默认全 `GFU85`。
5. **（可选）耗材颜色显示**：想要第三节的"看灯自检内部型号"，选**关掉**该选项那一级目录；想要 LED 显示真实耗材色，选 `FILAMENT_RGB_ON`。

> 文件名示例：`firmwares/standard(A1)/AUTOLOAD/FILAMENT_RGB_ON/AMS_A/ams_a_0.30f.bin` = 标准推力 / 双开关 / SOLO 槽 A / 0.30m 回抽。写死型号不体现在文件名里，由编译时决定。

## 七、刷写与兼容性

- 刷写工具用 **WCHISPTool**（不要用 BMCU Flasher，本仓库固件用它刷会失败）。
- 固件上报版本保持 `10.50`，打印机兼容性不变。
- 打印机固件建议不高于 **1.07.00**。

## 八、已知与待校准

- 各 TPU 型号的送料参数目前是**按硬度分级的初值**，还需在成品板上实测迭代校准（无串口，靠观察动作 + RGB 灯判断）。若你实测某个型号送料仍不理想，反馈具体现象，我们一起调参。
- TPU 85A 极软，官方建议禁用 PTFE 管；若坚持用 BMCU 送，已给最保守参数，但仍可能不稳定。

更详细的使用与选型说明请见仓库 `docs/BMCU使用指南.md`；开发细节见 `docs/BMCU开发说明.md`；编译相关见 `docs/编译指南.md`。
