# BMCU-C 固件发布说明 —— v4.0-tpu（开发中）

> 适用机型：BMCU 切料机（CH32V203C8T6 / RISC-V 版）
> 固件向打印机上报的版本号保持 `10.50`，兼容性不变。
> 本版是**大版本更替**，专门为 TPU 这类软料做了送料优化；原有 PLA/PETG 行为不变（通过编译开关隔离，普通固件仍是 v3.2 稳定版）。
---

## 一、本次更新了什么

- **新增 TPU 软料专用送料模式**：BMCU 以前对 PLA / PETG 这类"硬料"送得很好，但对 TPU（橡胶一样的软料）支持不好——料会被缓冲头压着"压缩"而不是顺畅前进，经常误报堵料、或者电机空转啃料。v4.0 针对 TPU 的每个型号单独调了送料参数（推料力度、保持时间、报堵宽容度），让它也能稳定送料。

- **每个 TPU 型号一套参数**：Bambu 的 TPU 有好几种，硬度差别很大（从 68D 的 TPU for AMS 到 85A 的极软 TPU），送料难度完全不同。v4.0 按型号分开调参：
  - `GFU98` Bambu TPU for AMS（68D，最硬，接近硬料）
  - `GFU00` Bambu TPU 95A HF / `GFU95` Bambu TPU 95A
  - `GFU02` Generic TPU for AMS
  - `GFU90` Bambu TPU 90A
  - `GFU85` Bambu TPU 85A（最软，参数最保守）

- **新增「看 RGB 灯验证识别」功能**：关闭「耗材颜色显示」后，通道灯不再只显示缓冲头状态，而是**按 BMCU 实际识别到的材料点亮**——每种 TPU 一个专属颜色，非 TPU 统一一种颜色，一眼就能确认 BMCU 到底有没有认对你的 TPU（详见第三节）。

- **新增「主板系统灯（SYS_RGB）显示 AHT20 环境传感器状态」**：2.0 起 BMCU 支持外接 AHT20 温湿度传感器，把环境温湿度上报给打印机。v4.0 用主板上的系统灯（不是通道灯）做**状态提示**：AHT20 握手成功后，每成功采到一次数据，系统灯就**呼吸式闪一下紫色**；若某次连续 3 次读取都失败，则闪一下琥珀色提示。AHT20 只是辅助传感器——没接、坏了、或读不到，BMCU 都照常工作，温湿度走默认 22℃ / 20%（详见第五节）。

> 通道灯 = 每个料槽一颗（显示耗材色 / TPU 识别色）；系统灯 = 主板上单独一颗（显示通讯与 AHT20 状态）。两者是不同灯，别混淆。

## 二、两种用法：通用固件（默认）+ 专用固件（兜底）

BMCU 是**多通道**的（4 槽 + SOLO），最常见的用法是**一个通道设 TPU、其他通道设 PLA/PETG 做支撑**——比如打 TPU 壳体、用 PLA 撑。这要求 BMCU 能按每个通道下发的材料，分别用不同推力参数送料。

v4.0 因此设计了两套固件，互不冲突：

### 2.1 通用固件（默认，推荐，支持运行时按通道识别 TPU）

- **编译时不需要指定 TPU 型号**，和 v3.2 一样全量编译即可。
- 装好材料后，打印机会把当前通道的材料型号下发给 BMCU；BMCU 读到某通道是 TPU（如 `GFU90`）后，**只对那个通道切换成对应 TPU 型号的软料推力参数**，其他通道（PLA/PETG/…）仍走原 v3.2 刚性推力。
- **打印过程中不会改动材料**，直到更换/重设材料才更新该通道参数。
- **任何通道都不设 TPU 时，固件行为 = 原版 v3.2，零差异**（TPU 参数表虽编入固件，但未被任何通道触发，不影响其它料）。

> 这是绝大多数场景（多料混打、TPU+PLA 支撑）的最优解：一块 BMCU 固件通吃，哪个槽放 TPU 哪个槽自动优化。

### 2.2 专用固件（兜底，仅老打印机用）

部分老打印机 / AMS **没法下发或识别 TPU 耗材型号**，BMCU 也就无从"运行时识别"。这时只能退而求其次：

> **编译时选定一个 TPU 型号，单独生成"TPU 专用固件"**（`BMCU_TPU_MODEL=型号`）。
> 刷进去后，**所有通道强制按该 TPU 型号参数送料**，不依赖打印机下发。
> 适用于"整台就只打 TPU、且打印机不支持材料设置"的情况。

## 三、怎么确认 BMCU 真的识别到你的 TPU（看 RGB 灯）

很多 TPU 送料问题，根因是"BMCU 没认出这是 TPU"，结果还在用 PLA 的硬推力去推软料。v4.0 加了一个**肉眼自检手段**：

- 把固件编译选项 **「耗材颜色显示」关掉**（即不选 `FILAMENT_RGB_ON` 那一级目录）。
- 装好料、通电后，看每个通道的**通道灯（每槽一颗）颜色**：

| 料卷标签（filament_id） | 型号 | 硬度 | 通道灯显示颜色 |
|---|---|---|---|
| GFU98 | TPU for AMS | 68D | 青 |
| GFU00 | TPU 95A HF | 95A | 绿 |
| GFU02 | Generic TPU | 约 68D | 紫 |
| GFU95 | TPU 95A | 95A | 黄 |
| GFU90 | TPU 90A | 90A | 橙 |
| GFU85 | TPU 85A | 85A | 红 |
| 非 TPU（PLA / PETG / ABS / PA / 未知 / other） | — | — | 白偏蓝（统一色） |

**怎么用**：
- 你放的是 `GFU90`，LED 却显示**白偏蓝** → 说明打印机没把 TPU 型号正确下发，BMCU 当普通料在推，要去检查打印机里的材料设置。
- LED 显示**橙色** → BMCU 确实认出了 `GFU90`，正常送料即可。
- 颜色对得上标签，就证明"识别链路通畅"，后续送料问题就不在识别这一层。

> 注意：开「耗材颜色显示」时，LED 仍显示打印机下发的真实耗材颜色（原有功能不变），此自检表不生效。自检用**关掉**该选项的状态。

## 四、TPU 送料是怎么优化的（两类推力逻辑要分清）

TPU 的送料优化其实分**两套互相独立**的逻辑，别混为一谈：

**① 常态送料（占 99% 时间）**
装好料正常往前送时，BMCU 用"压力闭环"控制推力。TPU 越软，目标压力带和推力上限越低——避免硬顶把软料压扁、或推力过猛啃料。这是"平时怎么温柔推"。

| 料 | 类型 | 送料力度 | 相对 PLA |
|---|---|---|---|
| PLA / PETG / ABS / PA | 刚性 | 基准（原力度） | 基准 |
| GFU98 / GFU02（约 68D） | TPU 偏硬 | 略降 | 略降 |
| GFU00 / GFU95（95A） | TPU | 降约 10-15% | 降约 10-15% |
| GFU90（90A） | TPU | 降约 20-25% | 降约 20-25% |
| GFU85（85A） | TPU | 降约 30-40% | 降约 30-40% |

> 越软 → 推力越小、目标压力越低，软料"顶不满"不代表没在正常工作，只是温柔推进。

**② 顶满避让（只在卡料兜底时接管）**
当料卡在五通/进挤出机、缓冲头被持续顶到极限时才触发，分三段逐步减小推力温柔退避，避免硬顶死。TPU 越软，避让力度越小、报堵的容忍时间越长——软料弹性大、容易"假顶满"，给更长窗口才判定真堵。

| 料 | 避让力度（卡住时） | 报堵容忍 | 趋势 |
|---|---|---|---|
| PLA / PETG | 原力度 | 基准（约 5 秒） | v3.2 原值 |
| GFU98 / GFU02（约 68D） | 略小 | 略长（约 6 秒） | 略保守 |
| GFU00 / GFU95（95A） | 更小 | 更长（约 7 秒） | 更小/更宽 |
| GFU90（90A） | 更保守 | 更长（约 8 秒） | 更保守 |
| GFU85（85A） | 最保守 | 最长（约 9 秒） | 最保守/最长 |

**一句话区别**：常态送料管"平时怎么推"，顶满避让管"卡住了怎么退"。两者都按 TPU 型号自动切换，非 TPU 仍走原 v3.2 逻辑。

## 五、主板系统灯（SYS_RGB）怎么显示 AHT20 状态

> 这是**主板上单独一颗灯（SYS_RGB）**，不是各料槽的通道灯。它本来就负责显示
> BMCU 与打印机的通讯状态（正常=浅灰白、掉线=红）。v4.0 在此基础上叠加了
> AHT20 环境传感器的状态提示。

### 5.1 AHT20 是什么、怎么工作

AHT20 是外接在 BMCU 上的温湿度传感器（焊在控制板上或通过插座连接），用来把
**环境温湿度**上报给打印机（在运动长包里，和送料状态一起）。它**只是辅助传感器**，
不参与送料、不影响 BMCU 任何核心功能。

- **开机时**：BMCU 会和 AHT20 握手一次，确认它是否存在、是否接好。
  - 握手成功 → 之后**每 10 秒**周期性读一次温湿度，成功就把真实值上报打印机。
  - 握手失败（没焊 / 坏了 / 没接）→ BMCU 认为"没有 AHT20"，温湿度直接走默认 **22℃ / 20%**，BMCU 完全正常，不报错、不卡死。
- **读取容错**：某次读取若失败，BMCU 会在本轮内**自动重试最多 3 次**；只要有一次成功就更新真实值；**连续 3 次都失败**才判定"本次采样失败"，此时温湿度**保留上一次成功的值**（没成功过就保持默认 22/20），下一轮（10 秒后）再试。

### 5.2 系统灯颜色含义（看灯判断 AHT20）

系统灯的颜色分**基色**（通讯状态，一直显示）和**呼吸提示**（瞬态，闪一下就回基色）：

| 系统灯状态 | 颜色 | 含义 |
|---|---|---|
| 基色：通讯正常 | 浅灰白 | BMCU 与打印机心跳正常（原有逻辑） |
| 基色：通讯失败 | 红 | BMCU 与打印机掉线 / 总线错误（原有逻辑，严重） |
| **呼吸提示：AHT20 成功上报** | 紫（呼吸闪一下） | 本周期成功读到一次 AHT20 温湿度（每 10 秒一次） |
| **呼吸提示：AHT20 读取失败** | 琥珀 / 橙（呼吸闪一下） | 本周期连续 3 次读 AHT20 都失败，值沿用上次（仅提示，不影响工作） |

**怎么用**：
- 接了 AHT20、通讯正常时，系统灯是浅灰白底、每 10 秒**紫色呼吸一下** → 说明环境数据在正常上报。
- 系统灯偶尔**闪一下琥珀色** → 某次读 AHT20 失败（瞬间干扰/接触不良），BMCU 已自动重试并沿用上次值，无需处理；若琥珀色频繁闪、且紫色很久不出现，检查 AHT20 接线。
- **系统灯完全不闪紫/琥珀、只有灰白或红** → 说明开机没识别到 AHT20（没接/坏了），温湿度走默认 22/20，BMCU 照常工作。
- 系统灯变**红** = 和打印机掉线，与 AHT20 无关，按原有通讯问题排查。

> AHT20 读取失败的琥珀提示，刻意不用红色——红色专指"和打印机断联"这种严重故障，
> 避免你把辅助传感器的小抖动误当成通讯故障。

## 六、怎么选固件（刷哪一个）

### 通用固件（绝大多数情况）

和 v3.2 一样选三点：**板型**、**打印机模式**、**PTFE 长度**。无需关心 TPU 型号——型号由打印机下发时自动识别。
1. **确认板型**：双开关 = AUTOLOAD；单开关 = NO_AUTOLOAD。
2. **确认打印机模式**：standard / p1s / soft_load(A1)（对应常规目录）。
3. **确认 PTFE 长度档**：见 `which_to_choose_slots.txt`。
4. **（可选）耗材颜色显示**：想要第三节的"看灯自检 TPU 识别"，选**关掉**该选项那一级目录；想要 LED 显示真实耗材色，选 `FILAMENT_RGB_ON`。

### 专用固件（老打印机兜底）

额外看第 4 点 **TPU 型号**：看料卷标签或 Bambu 官网，选对应型号后缀的固件（如 `.../GFU90/...`）。目录里 `standard(A1)/soft_load(A1)/high_force_load(P1S)` 这一级**已被型号名取代**（TPU 固件不区分推力模式，推力已在参数表里按硬度定制）。

> 文件名示例：`firmwares-tpu/GFU90/AUTOLOAD/FILAMENT_RGB_ON/SOLO/solo_2.00f_auto.bin` = TPU 90A 专用 / SOLO / 0.30m 回抽。

## 七、刷写与兼容性

- 刷写工具用 **WCHISPTool**（不要用 BMCU Flasher，本仓库固件用它刷会失败）。
- 固件上报版本保持 `10.50`，打印机兼容性不变。
- 打印机固件建议不高于 **1.07.00**。

## 八、已知与待校准

- 各 TPU 型号的送料参数目前是**按硬度分级的初值**，还需在成品板上实测迭代校准（无串口，靠观察动作 + RGB 灯判断）。若你实测某个型号送料仍不理想，反馈具体现象，我们一起调参。
- TPU 85A 极软，官方建议禁用 PTFE 管；若坚持用 BMCU 送，已给最保守参数，但仍可能不稳定。
