# BMCU RGB 灯含义速查（颜色 × 闪烁方式 → 行为 / 故障）

> 适用版本：v4.0-tpu（含 AHT20 驱动修复 v3.2.1-fix105）。
> 本文把 BMCU 上**所有 RGB 灯**的"亮什么颜色、怎么亮"对应到具体行为/故障，
> 方便肉眼判断状态、区分原版提示与 v4.0 新增提示，避免混淆。

---

## 0. 先认灯：这是两种不同的灯

BMCU 上有 **两套完全独立的 WS2812 灯**，GPIO 不同、含义不同，**别混淆**：

| 灯 | 物理位置 | 变量 | 负责什么 |
|---|---|---|---|
| **主板系统灯** | 主板上单独一颗 | `SYS_RGB` | 显示 BMCU 与打印机的**通讯状态** + v4.0 新增的 **AHT20 环境传感器状态** |
| **通道灯（每槽 2 颗，共 8 颗）** | 每个料槽各 2 颗 | `RGBOUT[0..3]`（每元素 `init(2,...)`） | 显示**该槽耗材颜色 / TPU 识别色**，以及该槽的送料动作/故障状态 |

> 一句话：系统灯看"整体通讯+AHT20"，通道灯看"每槽料的状态"。下文分两章。
>
> **硬件 / 固件现状说明**：每个料槽在硬件上接了 **2 颗** WS2812（`RGBOUT[i].init(2, ...)`），
> 即全机共 8 颗通道灯。但当前固件在设置颜色时统一用 `set_RGB(R,G,B,0)`（只写每槽
> 的第 0 颗），所以**目前实际点亮的是每槽第 0 颗，第 1 颗硬件存在但固件未单独驱动**
> （保持熄灭）。本文下述"通道灯颜色"均指该槽被点亮的灯（第 0 颗）所显示的颜色；
> 若后续需要两颗同显或分工显示，属于增强项，不在当前行为范围内。

## 1. 主板系统灯（SYS_RGB）

系统灯的颜色分两层：
- **基色（常亮）**：表示通讯状态，一直显示；
- **呼吸提示（瞬态，闪一下就回基色）**：v4.0 新增，表示 AHT20 事件。

| 系统灯状态 | 颜色 / 方式 | 含义 | 来源 |
|---|---|---|---|
| 启动瞬间 / 首心跳前 | 红（常亮） | 刚上电，还没和打印机建立通讯 | 原版 |
| 通讯正常 | 浅灰白 `0x38,0x35,0x32`（常亮，基色） | 与打印机心跳正常 | 原版 |
| 通讯失败 | 红 `0x10,0,0`（常亮，基色） | 与打印机掉线 / 总线错误（严重故障） | 原版 |
| **AHT20 成功上报一次** | **紫色呼吸**（灰白基色上，约 1s 三角波渐变紫 `0x60,0,0x80` 再渐回） | 本周期（每 10s）成功读到了一次 AHT20 温湿度 | **v4.0 新增** |
| **AHT20 读取失败** | **琥珀/橙呼吸**（灰白基色上，约 1s 渐变 `0xFF,0x60,0` 再渐回） | 本周期连续 3 次读 AHT20 都失败，温湿度沿用上次值（仅提示） | **v4.0 新增** |

**关键约束（避免迷惑）**
- 紫/琥珀呼吸**只在通讯正常（灰白基色）时**才叠加；一旦通讯失败变红，系统灯**不再闪紫/琥珀**，防止把"辅助传感器小抖动"误判成"通讯故障"。
- 呼吸是**柔和渐变**，不是硬切、不是快闪；如果看到系统灯"啪"地变紫又变回，那是正常的一次上报提示。
- AHT20 没接/坏了时：系统灯**完全不闪紫/琥珀**，只有灰白或红，温湿度走默认 22℃/20%，BMCU 正常工作。

## 2. 通道灯（RGBOUT，每槽 2 颗）

通道灯的显示内容由编译宏 **`BMCU_ONLINE_LED_FILAMENT_RGB`** 决定，两种模式含义不同：
（每槽硬件 2 颗，当前固件点亮第 0 颗，见第 0 节说明）

- **宏 ON（耗材颜色模式）**：显示打印机下发的**真实耗材色**；
- **宏 OFF（TPU 识别色模式，v4.0-tpu 新增）**：显示 BMCU **实际识别到的材料**——TPU 显示型号专属色，非 TPU 统一色，用来肉眼验证"程序到底有没有认对 TPU"。

**无论哪种模式，通道灯底色的"三态逻辑"和"动作/故障状态色"是共用的**（见 2.3）。

### 2.1 宏 ON：耗材颜色模式（原版）

底色（无送料动作时）三态：

| 条件 | 颜色 | 含义 |
|---|---|---|
| 料压 `pct ≥ hi_thr`（料满/顶满） | 红 `0x10,0,0` | 缓冲头被顶到高位 |
| 料压 `pct ≤ 30`（料少/空） | 蓝 `0,0,0x10` | 缓冲头低位 |
| 其他（有料且正常）且已识别耗材 | 打印机下发的真实耗材色（`color_R/G/B`） | 当前料卷的颜色 |

### 2.2 宏 OFF：TPU 识别色模式（v4.0-tpu 新增）

底色（无送料动作时）按**材料识别结果**显示：

| 识别到的材料 | 通道灯颜色 | 用途 |
|---|---|---|
| GFU98 / TPU for AMS (68D) | 青 | 一眼区分型号 |
| GFU00 / TPU 95A HF (95A) | 绿 | 一眼区分型号 |
| GFU02 / Generic TPU (~68D) | 紫 | 一眼区分型号 |
| GFU95 / TPU 95A (95A) | 黄 | 一眼区分型号 |
| GFU90 / TPU 90A (90A) | 橙 | 一眼区分型号 |
| GFU85 / TPU 85A (85A) | 红 | 一眼区分型号 |
| 非 TPU（PLA/PETG/ABS/PA/未知/other） | 白偏蓝 `0x08,0x08,0x10`（统一色） | 与任意 TPU 明显区分 |

> 关闭"耗材颜色显示"后，通道灯就变成"材料识别验证灯"：看到彩色=认到对应 TPU，看到白偏蓝=非 TPU。

### 2.3 动作 / 故障状态色（两种模式共用）

当某槽进入特定送料动作或故障时，通道灯**覆盖**底色，显示以下状态色：

| 状态 | 颜色 / 方式 | 含义 |
|---|---|---|
| 送料中 / 送出 (`send_out`) | 绿 `0x00,0xD5,0x2A`（稳定） | 正在把料送向打印头 |
| 准备上料 (`before_on_use`) | 黄 `0xFF,0xFF,0x00`（稳定） | 准备把料送到使用位 |
| 上料到位停 (`stop_on_use`) | 红 `0xFF,0,0`（稳定） | 料已送到使用位并停住 |
| 退料 / 拉回 (`pulling_back`) | 紫 `0xA0,0x2D,0xFF`，**闪烁**（红↔紫 1Hz 交替） | 正在把料拉回缓冲 |
| 卡料锁存（jam 未解除） | 绿（同送料中）+ 若处于低/卡料锁存则**红↔状态色 1Hz 闪** | 检测到真实堵料，需处理 |

> 注：紫色在通道灯上有两个来源——`pulling_back`（退料，紫闪）和 **TPU 识别色模式下的 GFU02 Generic TPU（紫，稳定）**。一个是"动作"一个是"材料"，靠**是否闪烁**区分（详见第 4 节易混淆点）。

### 1.1 上电自检灯序（AHT20 驱动修复 v3.2.1-fix105 后实机现象）

每次上电都会先跑一段**不阻塞主程序**的自检（`src/main.cpp` 中 `g_aht20.init()` + `read_blocking()`），系统灯用于开机自检与总线状态，与 4 颗通道灯互不冲突。

| 阶段 | 系统灯 | 含义 |
|------|--------|------|
| 开机固定 | 红（短亮） | 正常启动红灯 |
| AHT20 自检 | **蓝 → 绿（短亮）** | 蓝=检测到 AHT20 存在；绿=成功读到一次温湿度（v3.2.1-fix105 修复后可见） |
| 校准/初始化 | 灭（首次久、二次快） | 首次开机含校准耗时较长；二次开机已校准则很快 |
| 进入主循环（无 AHT20） | 浅灰 `0x38,0x35,0x32` 常亮 | 正常心跳 / 在线待命 |
| 进入主循环（有 AHT20） | 浅灰 `0x38,0x35,0x32` **每 3 秒闪一下（约 150ms）** | 灯珠靠近 AHT20 会发热烤高读数，故间歇闪烁而非常亮 |
| 总线/通讯错误 | 红 `0x10,0,0` | 收到 error 包（与 AHT20 无关，属原有通讯逻辑） |

> 自检蓝→绿亮过即说明 AHT20 驱动修复成功、传感器在线可读；若自检不亮灯（直接灭→进主程序），表示未检测到 AHT20 或未焊接，不影响换料/通讯，温湿度按默认 22℃/20% 上报。

系统灯颜色速查补充：

| RGB 值 | 含义 |
|--------|------|
| `0x10,0x00,0x00` | 红灯：开机启动 / 总线通讯错误 |
| `0x00,0x00,0x10` | 蓝灯（短）：AHT20 自检检测到存在 |
| `0x00,0x10,0x00` | 绿灯（短）：AHT20 自检成功读到温湿度 |
| `0x38,0x35,0x32` | 浅灰：正常心跳 / 在线待命（无 AHT20 常亮；有 AHT20 每 3 秒闪一下，防灯珠烤温） |

## 3. 首次开机校验灯语（校准流程）

> 这一节专门讲**首次刷写 / 手动重校准**时通道灯的提示。它和日常运行灯语完全不同，
> 只在"校准"这个特殊阶段出现，别和正常运行混淆。

### 3.1 什么时候会进入校准

`MC_PULL_calibration_boot()` 在开机时检查 Flash 里是否已有校准数据：
- **已有校准数据** → 直接加载，**无任何灯语**，正常启动；
- **没有校准数据**（首次刷写，或手动清校准）→ 进入校准流程：先 `Flash_NVM_full_clear()` 擦除，再采样、逐通道校准、写回 Flash。

> 手动重校准：取出所有料后，按住缓冲头约 **5 秒**触发 `MC_PULL_calibration_clear()`（清校准），下次开机即走上述流程。开发说明第 11 章有详述。

### 3.2 校准阶段的灯语序列（通道灯）

| 阶段 | 灯语 | 颜色 / 方式 | 含义 |
|---|---|---|---|
| 基准采样（~1.3s） | 所有**已插入**通道 | 红黄 `0x10,0x10,0x00` 与灭 **每 200ms 交替闪** | 正在采集缓冲头/微动开关基准电压 |
| 采样完成过渡 | 所有通道 | 黄 `0x10,0x10,0x00` **闪 3 次**（60ms 亮/60ms 灭） | 采样结束，进入逐通道校准 |
| 逐通道校准中 | 当前正在校的通道 | 蓝 `0x00,0x00,0x10` 与灭 **每 200ms 交替闪** | 该通道正在测行程上下限（让你轻拨缓冲头） |
| 逐通道校准等待手动拨动（超时前） | 当前通道 | 红 `0x10,0,0` 与灭 **每 200ms 交替闪** | 需要你手动拨动缓冲头以完成行程测量（若长时间不拨） |
| 单通道校准完成 | 该通道 | 熄灭 | 本通道 OK，进入下一通道 |
| **校准全部成功** | 所有通道 | **青 `0x00,0x10,0x10` 闪一下**（360ms 亮 / 180ms 灭） | Flash 擦除+写入成功，校准完成，即将正常启动 |
| **校准/写入失败** | 所有通道 | **红 `0x10,0,0` 闪一下**（460ms 亮 / 220ms 灭，比成功更长） | Flash 擦除或写入失败，需排查（可重试） |

> 注意：这里的"红闪一下（460ms）"是**校准失败**提示，和日常运行中"通道灯红闪=退料/卡料"虽然都是红闪，但**发生场景不同**（开机校准阶段 vs 正常运行阶段），且时长/节奏不同（单次长闪 vs 持续 1Hz 闪）。若开机后看到长红闪一下然后没正常进入工作，说明校准写入失败。

### 3.3 校准成功后

校准成功（青闪一下）后，BMCU 进入正常运行，通道灯随即切换到第 2 节的日常底色/状态色逻辑。此后除非再次手动清校准，否则开机不再有本节灯语。

## 4. 闪烁方式说明

BMCU 用两种"动态"方式提示异常/动作，注意区分：

- **稳定常亮**：正常状态色（绿=送料中、黄=准备上料、红=上料到位、各种底色）。
- **呼吸（系统灯专用）**：灰白基色上柔和渐变到紫/琥珀再渐回，约 1s 一次，表示 AHT20 事件（非故障，是"我刚上报了一次"或"这次读失败了"）。
- **1Hz 红色交替闪（通道灯专用）**：状态色与纯红 `0xFF,0,0` 每秒交替一次（`blink=1`）。**凡是通道灯在红闪，基本代表该槽处于"动作中/异常锁存"**（退料、卡料未解除等）。

## 5. 易混淆点（重点）

1. **同样是红色，意思天差地别**
   - 系统灯**红（常亮）** = BMCU 和打印机**断联**（严重）；
   - 通道灯**红（常亮）** = 该槽**上料到位停住**（正常动作）或料压顶满（底色三态）；
   - 通道灯**红闪** = 该槽**退料中/卡料锁存**（动作/异常）。
   → 看红灯先确认是**哪颗灯**。

2. **同样是紫色**
   - 系统灯**紫色呼吸** = AHT20 成功上报（每 10s 一次，柔和渐变）；
   - 通道灯**紫色稳定** = 识别到 GFU02 Generic TPU（TPU 识别色模式）；
   - 通道灯**紫色闪烁** = 该槽正在退料（`pulling_back`）。
   → 系统灯看"呼吸"，通道灯看"稳不稳"。

3. **绿色**
   - 通道灯绿稳定 = 送料中 / 卡料未解除仍尝试送；
   - （系统灯没有绿色提示。）

4. **AHT20 没接时系统灯不闪紫/琥珀**，这是正常的——不是 BMCU 故障，温湿度走默认 22/20。

## 6. 故障排查对照

| 你看到的现象 | 可能的原因 / 该做的 |
|---|---|
| 系统灯一直红（不回灰白） | BMCU 与打印机通讯失败：查接线、波特率、总线占用 |
| 系统灯灰白，每 10s 紫呼吸一下 | 正常：AHT20 在线且持续上报环境数据 |
| 系统灯灰白，偶尔琥珀呼吸一下 | AHT20 某次读失败（已重试 3 次仍失败），值沿用上次；偶发可忽略，频繁查 AHT20 接线 |
| 系统灯灰白，从不紫/琥珀 | 没接/未识别到 AHT20，温湿度走默认 22/20，BMCU 正常 |
| 某槽通道灯红闪（紫闪） | 该槽正在退料 / 卡料；卡料长时间不解除需人工处理 |
| 关掉耗材颜色后某槽显示白偏蓝 | 识别为非 TPU（PLA 等）；若你放的是 TPU，说明识别没对上 |
| 关掉耗材颜色后某槽显示青/绿/黄/橙/红（稳定） | 识别到对应型号 TPU，颜色对照 2.2 表确认型号 |
| 通道灯黄稳定 | 该槽准备上料（正常过渡态） |
| 通道灯绿稳定 | 该槽正在送料（正常） |
